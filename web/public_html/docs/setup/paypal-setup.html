PayPal Setup Guide

Configure PayPal Business for payments, Venmo, and Pay Later options with REST API integration and webhook support.

Part A: Vendor Setup

Follow these steps if you are the SIGNula platform owner configuring PayPal as a Level 1 payment provider.

1

Create a PayPal Business Account

Visit paypal.com and sign up for a Business account. If you already have a personal PayPal account, you can upgrade it to a Business account from your PayPal settings.

Note: A PayPal Business account is required to access the Developer Dashboard and create REST API apps. Personal accounts cannot generate API credentials.
2

Go to the Developer Dashboard

Navigate to developer.paypal.com and sign in with your PayPal Business account credentials. Click on My Apps & Credentials in the left sidebar.

3

Create a REST API App

Start by creating a Sandbox app for development and testing, then create a Live app for production.

  1. Select the Sandbox tab (or Live for production)
  2. Click Create App
  3. Enter an app name (e.g., "SIGNula Payments")
  4. Select the associated sandbox Business account
  5. Click Create App to generate credentials
Tip: Always build and test with Sandbox credentials first. PayPal provides pre-funded sandbox buyer and seller accounts for testing without real money.
4

Copy the Client ID and Client Secret

After creating the app, PayPal displays your credentials. Copy both values:

Client ID

// Sandbox Client ID AaBbCcDdEeFfGgHh...your_sandbox_client_id // Live Client ID AaBbCcDdEeFfGgHh...your_live_client_id

Client Secret

Click Show to reveal the Client Secret, then copy it.

// Sandbox Client Secret EHBWKknCcDd...your_sandbox_client_secret // Live Client Secret EHBWKknCcDd...your_live_client_secret
Security Warning: Never expose your Client Secret in client-side code or public repositories. SIGNula stores this value encrypted in the database with the isSensitive flag.
5

Set Up Webhooks

In the Developer Dashboard, select your app, then scroll down to the Webhooks section and click Add Webhook.

Webhook URL

https://yourdomain.com/webhooks/paypal

Events to Subscribe

Select the following event types that SIGNula listens for:

  • PAYMENT.CAPTURE.COMPLETED — Payment successfully captured
  • PAYMENT.CAPTURE.DENIED — Payment capture was denied
  • PAYMENT.CAPTURE.REFUNDED — Payment was refunded
  • BILLING.SUBSCRIPTION.CREATED — New subscription created
  • BILLING.SUBSCRIPTION.ACTIVATED — Subscription activated
  • BILLING.SUBSCRIPTION.UPDATED — Subscription details changed
  • BILLING.SUBSCRIPTION.CANCELLED — Subscription cancelled
  • BILLING.SUBSCRIPTION.SUSPENDED — Subscription suspended
  • BILLING.SUBSCRIPTION.PAYMENT.FAILED — Subscription payment failed

Copy the Webhook ID

After saving, PayPal generates a Webhook ID. Copy this value; it is used by SIGNula to verify incoming webhook notifications.

// Example Webhook ID format 5GP02834MN591234A
Important: Unlike Stripe, PayPal uses the Webhook ID (not a shared secret) for webhook verification. PayPal webhooks are verified by calling the PayPal API to confirm the event authenticity using the Webhook ID and transmission details.
6

Configure in SIGNula Admin Dashboard

Log in to your SIGNula Admin Dashboard and navigate to Admin → Payments → Providers → PayPal. Enter the following:

FieldValue
ModeSelect Sandbox or Live
Client IDYour sandbox or live Client ID
Client SecretYour sandbox or live Client Secret
Webhook IDThe Webhook ID generated by PayPal
7

Configure Funding Sources

Select which PayPal funding sources you want to offer your customers:

PayPal PayPal balance & linked accounts
Venmo US customers only
Pay Later Pay in 4 instalments
Card Debit & credit cards
Note: Venmo is only available for US-based buyers. Pay Later availability depends on the buyer's country and order amount. These options are controlled by PayPal based on eligibility.
8

Test the Connection

Click Test Connection in the SIGNula admin panel. This obtains an OAuth access token from the PayPal API to verify your Client ID and Client Secret are valid.

// SIGNula internally performs: POST https://api-m.sandbox.paypal.com/v1/oauth2/token Authorization: Basic {base64(client_id:client_secret)} Content-Type: application/x-www-form-urlencoded grant_type=client_credentials
Expected result: "Connection successful. PayPal OAuth token obtained. Webhook ID verified."
9

Enable the Provider

Toggle the Enabled switch to activate PayPal. It will now appear as a payment option during checkout.

Part B: Partner Setup

Partners can integrate PayPal using one of two models within SIGNula's two-tier payment architecture.

Level 2a: Partner Own Keys

Partners create their own PayPal REST API app and supply their own Client ID, Client Secret, and Webhook ID. Payments go directly to the partner's PayPal account.

Level 2b: Platform Keys

Partners use the SIGNula platform's PayPal credentials with per-transaction tracking. Revenue sharing is automated via the platform's billing system.

Level 2a: Steps for Partners Using Their Own Keys

1

Create Your Own PayPal Business Account

Sign up for a PayPal Business account and navigate to the Developer Dashboard at developer.paypal.com. Create a REST API app following Part A, Steps 2-4.

2

Configure the Partner Webhook Endpoint

In your PayPal REST API app, add a webhook pointing to your partner-specific SIGNula endpoint:

https://yourdomain.com/webhooks/paypal/{partner_id}

Subscribe to the same events listed in Part A, Step 5. Copy the generated Webhook ID.

3

Enter Credentials in Partner Dashboard

In your SIGNula Partner Dashboard, navigate to Payment Settings → PayPal. Enter your Client ID, Client Secret, and Webhook ID. Select the correct mode (Sandbox/Live) and click Save.

Level 2b: Using Platform Keys

For Level 2b, no PayPal configuration is required from the partner. The SIGNula platform administrator configures the revenue sharing percentage under Admin → Partners → Revenue Settings. Payments are tracked per-partner using metadata in each PayPal order.

Webhook Configuration

PayPal webhook verification differs from other providers. Instead of a shared secret, PayPal uses certificate-based verification via API call.

// PayPal webhook verification (simplified PHP) $payload = file_get_contents('php://input'); $headers = getallheaders(); // Extract PayPal transmission headers $transmissionId = $headers['PAYPAL-TRANSMISSION-ID'] ?? ''; $transmissionTime = $headers['PAYPAL-TRANSMISSION-TIME'] ?? ''; $certUrl = $headers['PAYPAL-CERT-URL'] ?? ''; $authAlgo = $headers['PAYPAL-AUTH-ALGO'] ?? ''; $transmissionSig = $headers['PAYPAL-TRANSMISSION-SIG'] ?? ''; // Verify via PayPal API $verifyPayload = [ 'auth_algo' => $authAlgo, 'cert_url' => $certUrl, 'transmission_id' => $transmissionId, 'transmission_sig' => $transmissionSig, 'transmission_time' => $transmissionTime, 'webhook_id' => $webhookId, // From tblSettings 'webhook_event' => json_decode($payload, true), ]; // POST to PayPal verification endpoint // Sandbox: https://api-m.sandbox.paypal.com/v1/notifications/verify-webhook-signature // Live: https://api-m.paypal.com/v1/notifications/verify-webhook-signature

Troubleshooting

Sandbox vs Live Confusion

  • Sandbox API base URL: https://api-m.sandbox.paypal.com
  • Live API base URL: https://api-m.paypal.com
  • Sandbox and Live apps have completely separate Client IDs and Secrets
  • Make sure the Mode setting in SIGNula matches the credentials you entered
  • Use PayPal sandbox buyer accounts (created in Developer Dashboard) for testing

"Authentication Failed" on Test Connection

  • Verify the Client ID and Client Secret are from the same app (sandbox or live)
  • Ensure no leading or trailing whitespace was included when pasting
  • Check that the REST API app has not been disabled in the Developer Dashboard
  • PayPal may block access if your Business account verification is incomplete

Webhook Delivery Failures

  • Confirm your webhook URL https://yourdomain.com/webhooks/paypal is publicly accessible over HTTPS
  • PayPal retries failed webhook deliveries for up to 3 days with exponential backoff
  • Check the Developer Dashboard under your app → Webhooks → Webhook Events for delivery status and HTTP response codes
  • Ensure your server returns 200 OK within 30 seconds
  • PayPal sandbox webhooks can sometimes be delayed; this is normal in sandbox mode

Webhook Verification Fails

  • Ensure the Webhook ID stored in SIGNula matches the one shown in the Developer Dashboard
  • PayPal verification requires an active OAuth token; check that your credentials are valid
  • Confirm you are calling the correct verification endpoint (sandbox vs live)
  • Verify no reverse proxy is stripping the PayPal-specific HTTP headers (PAYPAL-TRANSMISSION-ID, etc.)

Venmo or Pay Later Not Appearing

  • Venmo is only available for US-based buyers using eligible devices
  • Pay Later eligibility is determined by PayPal based on buyer country, order amount, and creditworthiness
  • Both funding sources must be enabled in your PayPal account settings and in SIGNula
  • These options do not appear in all sandbox environments
  • Ensure the PayPal JavaScript SDK is loaded with the correct enable-funding parameters

Settings Reference

All PayPal settings in tblSettings. Fields with are encrypted at rest (isSensitive = 1).

Setting KeyTypeDescription
payment.paypal.enabled Boolean Enable or disable PayPal as a payment provider
payment.paypal.mode String Operating mode: sandbox or live
payment.paypal.client_id String PayPal REST API Client ID (encrypted)
payment.paypal.client_secret String PayPal REST API Client Secret (encrypted)
payment.paypal.webhook_id String PayPal Webhook ID for webhook verification (encrypted)
payment.paypal.funding_sources JSON Enabled funding sources. Default: ["paypal","card"]
payment.paypal.venmo_enabled Boolean Enable Venmo as a funding source (US only)
payment.paypal.paylater_enabled Boolean Enable Pay Later / Pay in 4 instalment option
payment.paypal.currency String Default currency (ISO 4217). Default: USD
payment.paypal.brand_name String Brand name shown on PayPal checkout pages
