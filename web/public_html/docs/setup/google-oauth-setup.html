Google OAuth Setup

Configure Google OAuth 2.0 to enable "Sign in with Google" for both personal Google accounts and Google Workspace (organisational) accounts.

Overview

Google OAuth enables users to authenticate with SIGNula using their existing Google account. This supports both personal Google accounts (e.g., @gmail.com) and Google Workspace (organisational) accounts (e.g., @yourcompany.com).

SIGNula requests the following scopes from Google by default:

  • openid — Enables Single Sign-On (SSO) via OpenID Connect
  • email — Access to the user's email address
  • profile — Access to the user's name and profile picture
Tip: Google OAuth 2.0 uses the OpenID Connect (OIDC) protocol, which provides both authentication and basic user profile information in a single flow.

Prerequisites

  • A Google account (personal or Workspace)
  • Access to the Google Cloud Console
  • A registered domain for your SIGNula installation (e.g., signulo.id)
  • HTTPS enabled on your domain (required by Google for redirect URIs)

Step-by-Step Setup

1

Go to Google Cloud Console

Navigate to console.cloud.google.com and sign in with your Google account. If this is your first time using the Cloud Console, you may need to agree to the terms of service.

2

Create a New Project (or Select Existing)

At the top of the page, click the project dropdown (next to the Google Cloud logo), then click New Project.

  • Project name: SIGNula Auth
  • Organisation: Select your organisation (if applicable) or leave as "No organisation"
  • Click Create
Tip: If you already have a Google Cloud project you wish to use, simply select it from the project dropdown instead of creating a new one.
3

Enable Required APIs

Navigate to APIs & Services → Library in the left sidebar. Search for and enable the following APIs:

  • Google+ API — Required for basic OAuth sign-in flows
  • People API — Provides access to user profile data

Click the Enable button for each API.

4

Configure the OAuth Consent Screen

Navigate to APIs & Services → OAuth consent screen. Fill in the following details:

  • User Type:
    • External — Available to any user with a Google account (recommended for most SIGNula installations)
    • Internal — Only available to users within your Google Workspace organisation
  • App name: SIGNula
  • User support email: Your support email address
  • Authorised domains: Add your domain (e.g., signulo.id)
  • Developer contact information: Your email address

On the Scopes page, click Add or remove scopes and add:

  • openid
  • email
  • profile

On the Test users page, add any email addresses you want to use for testing while the app is in "Testing" mode.

Important: While your app is in "Testing" publishing status, only test users you explicitly add can sign in. You must submit for verification and publish the app to allow all users to authenticate.
5

Create OAuth Credentials

Navigate to APIs & Services → Credentials, then click Create Credentials → OAuth client ID.

  • Application type: Web application
  • Name: SIGNula Web Login
  • Authorised JavaScript origins:
    https://yourdomain.com
  • Authorised redirect URIs:
    https://yourdomain.com/oauth/callback

Click Create.

Note: You can add multiple redirect URIs if you have separate environments (e.g., https://localhost:8080/oauth/callback for local development).
6

Copy Client ID and Client Secret

After creating the OAuth client, a dialog will display your Client ID and Client Secret. Copy both values and store them securely.

Client ID: xxxxxxxxxxxx-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx.apps.googleusercontent.com Client Secret: GOCSPX-xxxxxxxxxxxxxxxxxxxxxxxxxx
Critical: The Client Secret is sensitive and should never be exposed in client-side code, committed to version control, or shared publicly. SIGNula stores it encrypted in the database (marked as isSensitive).
7

Configure SIGNula Admin Panel

Log in to your SIGNula Admin Panel and navigate to System → OAuth Providers → Google.

  • Enter the Client ID
  • Enter the Client Secret
  • The Redirect URI is auto-configured by SIGNula based on your installation domain
  • Click Save
Security: Both the Client ID and Client Secret are stored encrypted at rest in the SIGNula database using cryptographic encryption with salt.
8

Test the Integration

Visit your SIGNula login page and click the "Sign in with Google" button. You should be redirected to Google's consent screen. After granting permission, you will be redirected back to SIGNula and logged in.

Tip: If you are testing with the app in "Testing" mode, make sure you are signed in with a Google account that was added as a test user in step 4.

Scopes & Permissions

The following table describes each OAuth scope requested by SIGNula and what data it provides access to.

Scope Purpose Data Provided
openid Single Sign-On (SSO) Enables OpenID Connect authentication; provides a unique user identifier (sub claim)
email User email access The user's primary email address and whether it has been verified
profile Basic profile information User's full name, given name, family name, profile picture URL, and locale

Additional Scopes for Workspace Features

If your SIGNula installation requires deeper integration with Google Workspace (e.g., reading calendar data, managing contacts), additional scopes such as https://www.googleapis.com/auth/calendar.readonly or https://www.googleapis.com/auth/contacts.readonly can be configured. These require additional verification from Google and may trigger a more detailed consent screen for users.

Google Workspace Support

SIGNula fully supports authentication with Google Workspace (formerly G Suite) organisational accounts. When a user signs in with a Workspace account, SIGNula receives additional information about their organisation.

How Organisational Accounts Work

When a user authenticates with a Google Workspace account (e.g., user@yourcompany.com), the ID token includes the hd (hosted domain) claim, which indicates the Workspace domain. SIGNula can use this to restrict access to specific organisations or to tag users by domain.

Domain Verification

To display your organisation's name on the consent screen, you must verify domain ownership in the Google Cloud Console under Domain verification (found in the OAuth consent screen settings). This involves adding a DNS TXT record or uploading a verification file to your web server.

Admin Consent

Google Workspace administrators can pre-approve applications for their entire organisation. This is done through the Google Admin Console under Security → API controls → App access control. When admin consent is granted, individual users in the organisation will not see the consent screen.

Troubleshooting

redirect_uri_mismatch

This error occurs when the redirect URI in your OAuth request does not match any of the URIs configured in the Google Cloud Console. Ensure the redirect URI in SIGNula exactly matches (including protocol, domain, port, and path) one of the Authorised redirect URIs in your OAuth client configuration. Common causes include missing trailing slashes, using http instead of https, or typos in the domain name.

access_denied

The user declined to grant permission on the consent screen, or the app is in "Testing" mode and the user is not listed as a test user. Verify your app's publishing status and ensure the user's email is in the test users list if the app has not been published.

invalid_client

The Client ID or Client Secret is incorrect. Double-check that you have copied the correct values from the Google Cloud Console and that they are entered correctly in the SIGNula Admin Panel. Also verify that the OAuth client has not been deleted or disabled.

Consent Screen Not Verified

Google displays an "unverified app" warning screen when your app has not completed the verification process. To remove this warning, submit your app for verification in the OAuth consent screen settings. Google will review your app, which can take several days to several weeks. In the meantime, users can still proceed by clicking "Advanced" → "Go to [app name] (unsafe)".

Settings Reference

These settings are stored in tblSettings in the SIGNula backend database. Fields marked with are encrypted at rest.

Setting Key Type Description
oauth.google.enabled Boolean Enable or disable Google as a login provider
oauth.google.client_id String Google OAuth Client ID (encrypted, isSensitive)
oauth.google.client_secret String Google OAuth Client Secret (encrypted, isSensitive)
oauth.google.redirect_uri String Redirect URI after Google authentication (auto-configured)
oauth.google.scopes JSON JSON array of OAuth scopes. Default: ["openid","email","profile"]
oauth.google.hosted_domain String Optional: Restrict login to a specific Google Workspace domain (e.g., yourcompany.com). Leave empty to allow all domains.
oauth.google.prompt String OAuth prompt parameter. Options: none, consent, select_account. Default: select_account
