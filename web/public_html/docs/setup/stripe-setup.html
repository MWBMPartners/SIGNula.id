Stripe Setup Guide

Configure Stripe for credit/debit card payments, Stripe Link, Apple Pay, and Google Pay with full webhook integration.

Part A: Vendor (SIGNula Admin) Setup

Follow these steps if you are the SIGNula platform owner configuring Stripe as a Level 1 payment provider.

1

Create a Stripe Account

Visit stripe.com and create a new account. Complete the onboarding process including business verification and bank account details for payouts.

Tip: You can start testing immediately with Stripe's test mode before completing full business verification. No real charges will be processed in test mode.
2

Navigate to API Keys

In your Stripe Dashboard, go to Developers → API Keys. You will see both test and live key sets. Use test keys during development and switch to live keys for production.

3

Copy the Publishable Key

Copy your Publishable Key. This key is used on the client-side (browser) to securely tokenise card details.

// Test mode pk_test_51ABC...your_test_publishable_key // Live mode pk_live_51ABC...your_live_publishable_key
4

Copy the Secret Key

Copy your Secret Key. This is used server-side only and must never be exposed to the client. It authenticates all API requests to Stripe.

// Test mode sk_test_51ABC...your_test_secret_key // Live mode sk_live_51ABC...your_live_secret_key
Security Warning: Never expose your Secret Key in client-side code, public repositories, or log files. SIGNula stores this value encrypted in the database with the isSensitive flag.
5

Set Up Webhook Endpoint

Go to Dashboard → Developers → Webhooks → Add endpoint.

Endpoint URL

https://yourdomain.com/webhooks/stripe

Events to Select

Subscribe to the following events that SIGNula processes:

  • checkout.session.completed — Checkout payment completed
  • payment_intent.succeeded — Payment successfully captured
  • payment_intent.payment_failed — Payment attempt failed
  • customer.subscription.created — New subscription created
  • customer.subscription.updated — Subscription plan changed
  • customer.subscription.deleted — Subscription cancelled
  • invoice.paid — Recurring invoice paid
  • invoice.payment_failed — Recurring invoice payment failed

Copy the Webhook Signing Secret

After creating the endpoint, Stripe generates a Signing Secret starting with whsec_. Copy this value immediately.

whsec_your_webhook_signing_secret_here
Important: Each webhook endpoint has its own unique signing secret. If you create separate endpoints for test and live modes, each will have a different whsec_ value.
6

Configure in SIGNula Admin Dashboard

Log in to your SIGNula Admin Dashboard and navigate to Admin → Payments → Providers → Stripe. Enter the following:

FieldValue
ModeSelect Test or Live
Publishable KeyYour pk_test_... or pk_live_... key
Secret KeyYour sk_test_... or sk_live_... key
Webhook Signing SecretYour whsec_... value
7

Enable Payment Methods

In the Stripe configuration panel, enable the payment methods you wish to accept:

Card Visa, Mastercard, Amex
Stripe Link One-click checkout
Apple Pay iOS & macOS
Google Pay Android & Chrome
Note: Apple Pay requires domain verification in Stripe under Settings → Payment Methods. Google Pay requires the domain to be served over HTTPS.
8

Test the Connection

Click Test Connection in the SIGNula admin panel to verify your API keys are valid and the webhook endpoint is reachable.

Expected result: "Connection successful. Stripe API version: 2024-xx-xx. Webhook endpoint verified."
9

Activate the Provider

Toggle the Enabled switch to activate Stripe. It will now appear as a payment option during checkout.

Part B: Partner Setup (Two-Tier)

SIGNula supports two partner payment models. Choose the one that best fits your integration.

Level 2a: Partner Own Keys

Partners supply their own Stripe API keys. Payments go directly to the partner's Stripe account. Full control over refunds, disputes, and payouts.

Level 2b: Platform Keys

Partners use SIGNula platform's Stripe keys with per-transaction tracking and automated revenue sharing. Simpler setup; the platform processes on the partner's behalf.

Level 2a: Steps for Partners Using Their Own Keys

1

Create Your Own Stripe Account

Register at stripe.com and complete business verification. Generate your own Publishable Key, Secret Key, and set up webhooks following Part A, Steps 2-5.

2

Configure the Partner Webhook Endpoint

In your Stripe Dashboard, add a webhook pointing to your partner-specific SIGNula endpoint:

https://yourdomain.com/webhooks/stripe/{partner_id}

Subscribe to the same events listed in Part A, Step 5. Copy the Webhook Signing Secret for this endpoint.

3

Enter Credentials in Partner Dashboard

In your SIGNula Partner Dashboard, navigate to Payment Settings → Stripe. Enter your Publishable Key, Secret Key, and Webhook Signing Secret. Click Save then Test Connection.

Level 2b: Using Platform Keys

For Level 2b, no additional Stripe configuration is needed from the partner. The SIGNula platform administrator configures the revenue sharing split under Admin → Partners → Revenue Settings. Payments are tracked per-partner using metadata on each Stripe transaction.

Webhook Configuration

SIGNula verifies every incoming Stripe webhook using the Stripe-Signature header with HMAC-SHA256 and timestamp-based tolerance.

// Stripe webhook signature verification (simplified PHP) $payload = file_get_contents('php://input'); $sigHeader = $_SERVER['HTTP_STRIPE_SIGNATURE'] ?? ''; $secret = $decryptedWebhookSecret; // From tblSettings // Parse timestamp and signatures from the header $elements = explode(',', $sigHeader); $timestamp = ''; $signatures = []; foreach ($elements as $element) { $parts = explode('=', $element, 2); if ($parts[0] === 't') { $timestamp = $parts[1]; } elseif ($parts[0] === 'v1') { $signatures[] = $parts[1]; } } // Compute expected signature $signedPayload = $timestamp . '.' . $payload; $expectedSig = hash_hmac('sha256', $signedPayload, $secret); // Verify if (!in_array($expectedSig, $signatures, true)) { http_response_code(401); exit('Invalid webhook signature'); } // Process the event $event = json_decode($payload, true);

Webhook Events Reference

EventDescriptionSIGNula Action
checkout.session.completed Customer completed checkout Activates subscription or processes one-time payment
payment_intent.succeeded Payment successfully captured Credits user account; sends confirmation email
payment_intent.payment_failed Payment attempt was declined Logs failure; notifies user to update payment method
customer.subscription.created New subscription started Assigns tier and unlocks features for user
customer.subscription.updated Subscription plan or status changed Updates tier and feature access accordingly
customer.subscription.deleted Subscription was cancelled Revokes paid features; moves user to free tier
invoice.paid Recurring invoice successfully paid Extends subscription period; logs payment record
invoice.payment_failed Recurring invoice payment failed Sends dunning email; may suspend after retries

Troubleshooting

"Invalid API Key" on Test Connection

  • Verify you are using the correct key pair: test keys for Test mode, live keys for Live mode
  • Ensure you copied the full key without leading or trailing whitespace
  • Check the key has not been rolled or revoked in the Stripe Dashboard
  • Confirm you are using a standard Secret Key (sk_), not a Restricted Key (rk_)

Webhook Signature Verification Fails

  • Ensure the Webhook Signing Secret (whsec_...) matches exactly what Stripe shows for your endpoint
  • Each endpoint has its own unique signing secret; verify you copied the correct one
  • Check that no proxy or middleware is modifying the raw POST body before SIGNula receives it
  • Verify your server clock is synchronised (Stripe enforces a 5-minute timestamp tolerance)

Webhooks Not Being Received

  • Confirm https://yourdomain.com/webhooks/stripe is publicly accessible (not behind a firewall or VPN)
  • Verify your SSL/TLS certificate is valid (Stripe requires HTTPS)
  • In Stripe Dashboard, check Developers → Webhooks for delivery attempts and error codes
  • Ensure your server returns 200 OK within 20 seconds
  • For local development, use Stripe CLI: stripe listen --forward-to localhost:8000/webhooks/stripe

Test vs Live Mode Confusion

  • Test keys: pk_test_ / sk_test_. Live keys: pk_live_ / sk_live_
  • Separate webhook endpoints are needed for test and live modes in Stripe
  • Match the Mode setting in SIGNula to your key set
  • Use Stripe test card numbers (e.g., 4242 4242 4242 4242) in test mode

Apple Pay / Google Pay Not Appearing

  • Apple Pay requires domain verification in Stripe under Settings → Payment Methods
  • Google Pay requires the domain to be registered and served over HTTPS
  • Both must be enabled in SIGNula's Stripe configuration panel
  • Apple Pay only appears on Safari (macOS/iOS); Google Pay on Chrome and Android browsers

Settings Reference

All Stripe settings in tblSettings. Fields with are encrypted at rest (isSensitive = 1).

Setting KeyTypeDescription
payment.stripe.enabled Boolean Enable or disable Stripe as a payment provider
payment.stripe.mode String Operating mode: test or live
payment.stripe.publishable_key String Stripe Publishable Key (encrypted)
payment.stripe.secret_key String Stripe Secret Key (encrypted)
payment.stripe.webhook_secret String Webhook Signing Secret for signature verification (encrypted)

payment.stripe.google_pay_enabled Boolean Enable Google Pay through Stripe Payment Element
payment.stripe.currency String Default currency (ISO 4217). Default: USD
payment.stripe.statement_descriptor String Text on customer bank statements (max 22 chars)
