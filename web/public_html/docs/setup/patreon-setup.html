Patreon Setup

Integrate Patreon membership tiers with SIGNula subscription levels. Patreon uses OAuth 2.0 for authentication and webhooks for real-time membership event notifications. The API follows the JSON:API specification.

Part A: Vendor (Platform Owner) Setup

Follow these steps if you are the SIGNula platform owner and want to integrate Patreon membership management with your application.

1

Log In to Your Patreon Creator Account

Visit patreon.com and log in with your creator account. You must have a creator account (not just a patron account) to access the developer portal and create API clients.

2

Navigate to the Developer Portal

Go to patreon.com/portal and click the "My Clients" tab. This is where you manage your API clients (also known as Platform clients).

Tip: If you do not see the "My Clients" tab, ensure you are logged in with a creator account that has an active Patreon page.
3

Create a New Platform Client

Click "Create Client" to register a new API application.

4

Fill In Client Details

Complete the registration form with the following details:

Field Example Value Notes
App Name SIGNula Integration A descriptive name for your integration
Description SIGNula membership tier sync Brief description of what the integration does
App Category Community / Membership Select the most relevant category
Redirect URI https://yourdomain.com/auth/patreon/callback OAuth 2.0 callback URL where Patreon redirects after authorisation
5

Copy Client ID and Client Secret

After creating the client, you will be shown:

  • Client ID — A public identifier for your application.
  • Client Secret — A confidential key used for OAuth token exchanges.
Critical: Copy the Client Secret immediately and store it securely. It may only be displayed once. If lost, you will need to regenerate it.
6

Set Up Webhooks

Under your client settings in the developer portal, find the Webhooks section and configure as follows:

  1. Set the Webhook URL: 
    https://yourdomain.com/webhooks/patreon
  2. Select the following webhook triggers:
    • members:pledge:create
    • members:pledge:update
    • members:pledge:delete
    • members:create
    • members:update
    • members:delete
  3. Save the webhook configuration.
  4. Copy the Webhook Secret that is generated.
Important: Patreon uses HMAC-MD5 (not SHA-256) for webhook signature verification via the X-Patreon-Signature header. This is a key difference from other providers.
7

Obtain Creator Access Token

A Creator Access Token allows SIGNula to make API calls on behalf of your creator account (e.g., fetching campaign data, listing members). You can obtain it in two ways:

  • Option A: Use the OAuth 2.0 flow to obtain an access token and refresh token.
  • Option B: Generate a Creator Access Token directly from the developer portal (shown under your client's settings).
# OAuth 2.0 token exchange (Option A)
curl -X POST https://www.patreon.com/api/oauth2/token \
  -d "code=AUTHORIZATION_CODE" \
  -d "grant_type=authorization_code" \
  -d "client_id=YOUR_CLIENT_ID" \
  -d "client_secret=YOUR_CLIENT_SECRET" \
  -d "redirect_uri=https://yourdomain.com/auth/patreon/callback"
Tip: Option B (portal-generated token) is simpler for initial setup. SIGNula will automatically refresh the token using the refresh token when it expires.
8

Get Your Campaign ID

Your Campaign ID is needed to query membership data. Fetch it using the API: 

# Fetch campaign data to get your Campaign ID
curl -X GET "https://www.patreon.com/api/oauth2/v2/campaigns" \
  -H "Authorization: Bearer YOUR_CREATOR_ACCESS_TOKEN" \
  -H "Content-Type: application/json"

The response will include your campaign(s):

{
    "data": [
        {
            "type": "campaign",
            "id": "1234567",
            "attributes": {
                "creation_name": "My Creator Page",
                "patron_count": 150,
                "is_monthly": true
            }
        }
    ]
}

Note the "id" value (e.g., 1234567) — this is your Campaign ID.

9

Configure SIGNula Admin Panel

Enter all your Patreon credentials into SIGNula:

  1. Log in to your SIGNula Admin Panel.
  2. Navigate to Payments → Providers → Patreon.
  3. Toggle the Enabled switch to activate Patreon.
  4. Enter your Client ID.
  5. Enter your Client Secret.
  6. Enter your Webhook Secret.
  7. Enter your Creator Access Token.
  8. Enter your Campaign ID.
  9. Optionally toggle Sync Members to periodically synchronise member data.
  10. Click Save Settings.
10

Test the Connection

Click the Test Connection button. SIGNula will:

  • Make an authenticated API call to /api/oauth2/v2/campaigns/{campaign_id}.
  • Verify the Creator Access Token is valid and has the necessary scopes.
  • Confirm the Campaign ID exists and is accessible.
  • Display campaign name and patron count on success.
Note: If the test fails with a 401 error, your access token may have expired. SIGNula will attempt to refresh it automatically using the stored refresh token.

Part B: Partner Setup

Partners who want to integrate their own Patreon campaigns with SIGNula follow the same process as Part A, using their own creator accounts.

1

Create Your Own Patreon API Client

Each partner must register their own API client in the Patreon developer portal. Use a partner-specific redirect URI: 

https://yourdomain.com/auth/patreon/callback/{partner_id}
2

Enter Credentials in Partner Dashboard

In the SIGNula Partner Dashboard, navigate to Settings → Payment Providers → Patreon and enter all credentials (Client ID, Client Secret, Webhook Secret, Creator Access Token, Campaign ID).

3

Map Patreon Tiers to SIGNula Tiers

Use the Tier Mapping section in the Partner Dashboard to map each Patreon membership tier to a corresponding SIGNula subscription tier. See the Tier Mapping section below for details.

Webhook Events

Patreon sends webhook notifications via the X-Patreon-Event header. SIGNula processes these automatically to manage membership status.

X-Patreon-Event Header Description SIGNula Action
members:pledge:create A new patron has pledged to your campaign Creates or activates subscription at the mapped SIGNula tier
members:pledge:update A patron has changed their pledge amount or tier Updates subscription tier mapping; adjusts access level
members:pledge:delete A patron has cancelled their pledge Deactivates subscription; reverts to free tier
members:create A new member has been added (may not have an active pledge) Records member association; no tier activation
members:update Member information has been updated Updates member record in SIGNula database
members:delete A member has been removed from the campaign Removes Patreon association; deactivates subscription

Tier Mapping

Map your Patreon membership tiers to SIGNula subscription tiers so that when a patron pledges at a certain level, SIGNula automatically grants the correct access.

Patreon: Bronze Supporter ($3/month)
SIGNula: Basic
Patreon: Silver Supporter ($10/month)
SIGNula: Pro
Patreon: Gold Supporter ($25/month)
SIGNula: Premium

Tier mapping is stored as JSON in the payment.patreon.tier_mapping setting: 

// Example tier_mapping JSON
{

        "9876543": {

            "patreon_amount_cents": 300,

            "signula_tier_name": "Basic"
        },

            "patreon_name": "Silver Supporter",
            "patreon_amount_cents": 1000,
            "signula_tier_id": "tier_pro",
            "signula_tier_name": "Pro"

        "9876545": {
            "patreon_name": "Gold Supporter",

API Details

Property Value
API Base URL https://www.patreon.com/api/oauth2/v2
API Format JSON:API specification (jsonapi.org)
Authentication Authorization: Bearer ACCESS_TOKEN
Content Type application/json
Webhook Event Header X-Patreon-Event
Webhook Signature Header X-Patreon-Signature
Webhook Signature Algorithm HMAC-MD5

Webhook Verification

Patreon signs webhooks using HMAC-MD5 with your Webhook Secret. The signature is sent in the X-Patreon-Signature header.

Important: Patreon uses HMAC-MD5, which is less common than HMAC-SHA256. Ensure your verification code uses the md5 algorithm, not sha256. 
// Patreon webhook verification in PHP (simplified)
$payload   = file_get_contents('php://input');
$sigHeader = $_SERVER['HTTP_X_PATREON_SIGNATURE'] ?? '';
$event     = $_SERVER['HTTP_X_PATREON_EVENT'] ?? '';
$secret    = $decryptedWebhookSecret; // Retrieved & decrypted from tblSettings

// IMPORTANT: Patreon uses HMAC-MD5, NOT HMAC-SHA256
$expectedSig = hash_hmac('md5', $payload, $secret);

if (!hash_equals($expectedSig, $sigHeader)) {
    // Signature mismatch - reject the request
    http_response_code(401);
    exit('Invalid signature');
}

// Signature valid - process the event
$data = json_decode($payload, true);

// The event type is in the header, NOT in the payload
switch ($event) {
    case 'members:pledge:create':
        // Handle new pledge
        break;
    case 'members:pledge:update':
        // Handle pledge update
        break;
    case 'members:pledge:delete':
        // Handle pledge cancellation
        break;
    // ... handle other events
}

Settings Reference

These settings are stored in tblSettings in the SIGNula backend database. Fields marked with are encrypted at rest.

Setting Key Type Description
payment.patreon.enabled Boolean Enable or disable Patreon as a payment/membership provider
payment.patreon.client_id String Patreon API Client ID (encrypted, isSensitive)
payment.patreon.client_secret String Patreon API Client Secret (encrypted, isSensitive)
payment.patreon.webhook_secret String Webhook secret for HMAC-MD5 signature verification (encrypted, isSensitive)
payment.patreon.campaign_id String Your Patreon Campaign ID
payment.patreon.creator_access_token String OAuth 2.0 access token for API calls (encrypted, isSensitive)
payment.patreon.creator_refresh_token String OAuth 2.0 refresh token for renewing access (encrypted, isSensitive)
payment.patreon.tier_mapping JSON JSON mapping of Patreon tier IDs to SIGNula tier IDs
payment.patreon.webhook_url String The configured webhook URL for Patreon events
payment.patreon.log_all_events Boolean If enabled, logs all incoming Patreon events to the activity log
payment.patreon.sync_members Boolean If enabled, periodically syncs member data from Patreon API

Troubleshooting

  • Your Creator Access Token may have expired. Patreon tokens have a limited lifetime.
  • Check if the refresh token is still valid. SIGNula attempts automatic refresh on 401 responses.
  • Try generating a new Creator Access Token from the developer portal.
  • Verify the Client ID and Client Secret are correct.
  • Ensure the token has the required scopes: identity, campaigns, campaigns.members.

  • Patreon uses HMAC-MD5, not HMAC-SHA256. Ensure your code uses hash_hmac('md5', ...).
  • Verify the Webhook Secret in SIGNula matches what Patreon shows in the developer portal.
  • Ensure you are reading the raw request body without modifications.
  • Check that no proxy or middleware is altering the request payload.

  • Verify the Campaign ID by calling the /campaigns endpoint directly.
  • Ensure you are using the numeric Campaign ID, not the page slug or vanity URL.
  • Confirm the Creator Access Token belongs to the same account that owns the campaign.
  • Check that your campaign is active and not archived.

  • Verify the payment.patreon.tier_mapping JSON contains the correct Patreon tier IDs.
  • Patreon tier IDs are numeric strings. You can find them by querying /campaigns/{id}?include=tiers.
  • Ensure the SIGNula tier IDs referenced in the mapping actually exist in your SIGNula tier configuration.
  • If a patron is on a tier not in the mapping, SIGNula will log a warning but not activate any tier.

  • Verify the webhook URL in the Patreon developer portal matches your SIGNula endpoint.
  • Ensure your endpoint is publicly accessible over HTTPS.
  • Patreon may disable webhooks that consistently fail. Check the webhook status in the developer portal.
  • Your endpoint must return a 2xx response within a reasonable timeframe.
  • Check your server's access logs for incoming POST requests from Patreon.
  • Enable payment.patreon.log_all_events and review the SIGNula activity log.

  • Ensure payment.patreon.sync_members is set to true.
  • Verify the Creator Access Token has the campaigns.members scope.
  • The Patreon API paginates results. SIGNula handles pagination automatically, but check for errors in the activity log.
  • Large campaigns with thousands of patrons may take several minutes to fully sync.
  • Check the Patreon API rate limits (currently ~720 requests per hour).
