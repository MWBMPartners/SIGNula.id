Patreon Setup

Connect Patreon for membership-based recurring payments and tiered access. Patreon uses OAuth 2.0 API v2 for authentication and webhooks for real-time membership event notifications.

Overview

Patreon is a membership platform that allows creators to earn recurring revenue from supporters ("patrons") through tiered subscription plans. SIGNula integrates with Patreon via its API v2 (which uses the JSON:API specification) and webhooks to synchronise membership status, manage tier-based feature access, and process pledge events in real time.

Integration Type

Model: OAuth 2.0 + REST API v2 + Webhooks
API Format: JSON:API specification (responses use data, included, relationships structure)
Authentication: OAuth 2.0 Bearer Token + Creator Access Token for server-side API calls
Webhook Verification: HMAC-MD5 via X-Patreon-Signature header
Event Type Header: X-Patreon-Event header (NOT in the body)

Important: Patreon webhook signatures use HMAC-MD5, not HMAC-SHA256 like most other providers. The event type is also sent in the X-Patreon-Event HTTP header, not in the webhook body payload. Ensure your implementation accounts for these differences.

Prerequisites

  • A Patreon creator account at patreon.com
  • An active Patreon campaign with at least one membership tier configured
  • A publicly accessible HTTPS endpoint for webhooks and OAuth callbacks
  • SIGNula Admin Panel access (for vendor setup) or Partner Dashboard access (for partner setup)
Note: Patreon API v2 is the current and recommended version. API v1 is deprecated. SIGNula exclusively uses API v2 with JSON:API format responses.

Part A: Vendor (Platform Owner) Setup

Follow these steps if you are the SIGNula platform owner and want to integrate Patreon membership tiers with your platform's subscription system.

1

Create a Patreon Creator Account

Visit patreon.com and create a creator account if you do not already have one. Ensure your campaign is set up with the membership tiers you want to map to SIGNula subscription levels.

2

Navigate to My Clients (Platform Section)

Go to patreon.com/portal and find the My Clients section under the Platform area. This is where you create and manage API clients for your integration.

3

Create a New API Client

Click Create Client and fill in the following details:

  • App Name: SIGNula Integration
  • Description: A brief description of your integration (e.g., "SIGNula membership and payment integration")
  • App Category: Choose the most appropriate category
  • Redirect URIs: 
    https://yourdomain.com/oauth/callback
Note: The Redirect URI must exactly match what SIGNula sends during the OAuth flow. Include the full URL with HTTPS and no trailing slash.
4

Copy Client ID and Client Secret

After creating the client, Patreon will display your Client ID and Client Secret. Copy both values immediately and store them securely. 

# Example Client ID format:
abcdef1234567890abcdef1234567890abcdef12

# Example Client Secret format:
xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
Critical: The Client Secret is only shown once upon creation. Copy it immediately and store it in a secure location such as a password manager. If you lose it, you will need to regenerate it.
5

Get Your Campaign ID

Your Campaign ID identifies your specific Patreon campaign. You can find it via:

  • From the portal: Navigate to patreon.com/portal → Campaigns and note the campaign ID in the URL.
  • Via the API: Make an authenticated API call: 
    GET https://www.patreon.com/api/oauth2/v2/campaigns
Authorization: Bearer YOUR_CREATOR_ACCESS_TOKEN

The response will contain your campaign(s) in JSON:API format. The data[0].id field is your Campaign ID.

6

Generate a Creator Access Token

The Creator Access Token is a long-lived token that allows SIGNula to make API calls on behalf of your campaign (e.g., fetching tiers, member data).

  1. Go to Settings → Manage Clients.
  2. Click on your API client.
  3. Find the Creator's Access Token section.
  4. Click Generate to create a new token.
  5. Copy the token immediately.
Important: The Creator Access Token grants full read access to your campaign data including member details. Treat it with the same security as a password. It is used for server-side API calls to fetch tiers and member data.
7

Add Webhook

Configure webhooks to receive real-time notifications when membership events occur:

  1. Edit your API client in the Patreon portal.
  2. Find the Webhooks section.
  3. Enter your webhook URL: 
    https://yourdomain.com/webhooks/patreon
  4. Select the following webhook triggers:
    • members:pledge:create — New pledge created
    • members:pledge:update — Pledge updated (tier change, amount change)
    • members:pledge:delete — Pledge cancelled or deleted
    • members:create — New member joined campaign
    • members:update — Member details updated
    • members:delete — Member removed from campaign
  5. Save the webhook configuration.
  6. Copy the Webhook Secret that is generated.
HMAC-MD5 Verification: Patreon uses HMAC-MD5 (not SHA256) for webhook signature verification. The signature is sent in the X-Patreon-Signature header. The event type is in the X-Patreon-Event header, NOT in the request body.
8

Configure SIGNula Admin Panel

Now enter your credentials into SIGNula:

  1. Log in to your SIGNula Admin Panel.
  2. Navigate to Admin → Payments → Providers → Patreon.
9

Enter All Credentials

In the Patreon provider settings, enter the following:

  • Client ID — from step 4
  • Client Secret — from step 4
  • Webhook Secret — from step 7
  • Creator Access Token — from step 6
  • Campaign ID — from step 5
Security: The Client Secret, Webhook Secret, Creator Access Token, and Creator Refresh Token are all stored encrypted in the SIGNula database (marked as isSensitive).
10

Optional: Enable Sync Members

Toggle the Sync Members switch to enable automatic synchronisation of your Patreon member list with SIGNula. When enabled, SIGNula will periodically fetch your campaign's member data via the API to ensure membership status is current, in addition to real-time webhook notifications.

11

Test Connection and Enable

Click the Test Connection button. SIGNula will:

  • Authenticate with the Patreon API using your Creator Access Token.
  • Fetch your campaign details and verify the Campaign ID.
  • Retrieve the list of tiers for tier mapping.
  • Verify the webhook endpoint is reachable.
# SIGNula internally performs requests like:
curl -X GET "https://www.patreon.com/api/oauth2/v2/campaigns/{campaign_id}" \
  -H "Authorization: Bearer YOUR_CREATOR_ACCESS_TOKEN" \
  -H "Content-Type: application/json"

# To fetch tiers:
curl -X GET "https://www.patreon.com/api/oauth2/v2/campaigns/{campaign_id}?include=tiers&fields[tier]=title,amount_cents,description" \
  -H "Authorization: Bearer YOUR_CREATOR_ACCESS_TOKEN"

Once the test passes, toggle the Enabled switch to activate Patreon as a payment provider.

Success: Patreon is now configured. Membership events (pledges, cancellations, tier changes) will be processed by SIGNula in real time.

Part B: Partner Setup

Partners who want to connect their own Patreon campaigns must set up their own API client and provide their credentials to SIGNula.

1

Create Your Own Patreon Campaign

Each partner must have their own Patreon creator account and active campaign at patreon.com. Set up your membership tiers before proceeding.

2

Create an API Client

Follow the same steps as Part A (steps 2-7) to create your own API client, generate credentials, and configure webhooks. Use the partner-specific webhook URL provided by SIGNula: 

https://yourdomain.com/webhooks/patreon/{partner_id}
3

Enter Credentials in Partner Dashboard

In your SIGNula Partner Dashboard, navigate to Settings → Payment Providers → Patreon and enter:

  • Your Client ID and Client Secret
  • Your Webhook Secret
  • Your Creator Access Token
  • Your Campaign ID
  • Map your Patreon tiers to SIGNula subscription tiers

Webhook Configuration

Webhook Event Triggers

Event Trigger Description SIGNula Action
members:pledge:create A new patron has pledged to your campaign Creates membership; activates corresponding tier
members:pledge:update A patron has changed their pledge amount or tier Updates tier assignment; adjusts feature access
members:pledge:delete A patron has cancelled or deleted their pledge Deactivates membership; revokes tier access
members:create A new member has joined your campaign (free or paid) Creates member record in SIGNula
members:update A member's details have been updated Updates member profile data
members:delete A member has been removed from your campaign Removes member record; revokes all access

Webhook Verification (HMAC-MD5)

Critical Difference: Patreon uses HMAC-MD5 for webhook signature verification, NOT HMAC-SHA256. The signature is in the X-Patreon-Signature header. The event type is in the X-Patreon-Event header, NOT in the request body. 
// Webhook verification in PHP (simplified)
$payload   = file_get_contents('php://input');
$signature = $_SERVER['HTTP_X_PATREON_SIGNATURE'] ?? '';
$eventType = $_SERVER['HTTP_X_PATREON_EVENT'] ?? '';
$secret    = $decryptedWebhookSecret; // Retrieved & decrypted from tblSettings

// IMPORTANT: Patreon uses HMAC-MD5, NOT SHA256
$expectedSig = hash_hmac('md5', $payload, $secret);

if (!hash_equals($expectedSig, $signature)) {
    // Signature mismatch - reject the request
    http_response_code(401);
    exit('Invalid signature');
}

// Signature valid - process the event
// Event type comes from the HEADER, not the body
switch ($eventType) {
    case 'members:pledge:create':
        // Handle new pledge
        break;
    case 'members:pledge:update':
        // Handle pledge update
        break;
    case 'members:pledge:delete':
        // Handle pledge cancellation
        break;
    case 'members:create':
        // Handle new member
        break;
    case 'members:update':
        // Handle member update
        break;
    case 'members:delete':
        // Handle member removal
        break;
}

// Parse the JSON:API format body
$data = json_decode($payload, true);

JSON:API Response Format

Patreon API v2 uses the JSON:API specification. Responses include data, included, and relationships objects rather than flat JSON. Webhook bodies also follow this format. 

// Example webhook body (JSON:API format, simplified):
{
    "data": {
        "id": "member_123456",
        "type": "member",
        "attributes": {
            "full_name": "Jane Supporter",
            "email": "jane@example.com",
            "patron_status": "active_patron",
            "currently_entitled_amount_cents": 500,
            "pledge_relationship_start": "2026-01-15T00:00:00.000+00:00"
        },
        "relationships": {
            "currently_entitled_tiers": {
                "data": [
                    { "id": "tier_789", "type": "tier" }
                ]
            },
            "campaign": {
                "data": { "id": "campaign_456", "type": "campaign" }
            }
        }
    },
    "included": [
        {
            "id": "tier_789",
            "type": "tier",
            "attributes": {
                "title": "Pro Supporter",
                "amount_cents": 500,
                "description": "Access to Pro features"
            }
        }
    ]
}

Troubleshooting

Test Connection fails with "Unauthorized"

  • Verify the Creator Access Token is correct and has not expired.
  • Ensure you are using the Creator Access Token (not the Client Secret) for API calls.
  • Try generating a new Creator Access Token from the Patreon portal.
  • Check that the API client has not been deleted or disabled.

Webhook signature verification fails

  • Ensure you are using HMAC-MD5, not HMAC-SHA256.
  • Verify the Webhook Secret in SIGNula matches exactly what Patreon generated.
  • Read the raw request body from php://input without modification.
  • Check that no middleware or proxy is altering the request body before verification.
  • The signature header is X-Patreon-Signature (case-insensitive).

Event type not being detected

  • The event type is in the X-Patreon-Event header, not in the body.
  • In PHP, access it via $_SERVER['HTTP_X_PATREON_EVENT'].
  • Do NOT look for an "event" or "type" field in the JSON body for the event name.

Campaign ID not found

  • Verify you are using the correct Campaign ID (numeric string).
  • Try fetching it via the API: GET /api/oauth2/v2/campaigns with your Creator Access Token.
  • Ensure your Patreon campaign is active and not in draft mode.

Tier mapping not working correctly

  • Use the Sync Tiers button in SIGNula to refresh the list of Patreon tiers.
  • Check that each Patreon tier is mapped to a SIGNula subscription tier.
  • Remember that Patreon amounts are in cents (e.g., 500 = $5.00).
  • Verify the currently_entitled_tiers relationship in webhook data is being parsed correctly.

JSON:API response parsing errors

  • Remember that Patreon API v2 uses JSON:API format, not standard flat JSON.
  • Primary data is in $response['data']; related resources are in $response['included'].
  • Attributes are nested under $response['data']['attributes'].
  • Relationships reference IDs that must be resolved from the included array.
