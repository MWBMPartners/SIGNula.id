Facebook OAuth Setup

Facebook Login enables users to sign in with their Facebook or Instagram (Meta) accounts. SIGNula requests the email and public_profile scopes to authenticate users and retrieve basic profile information. Supports personal Facebook accounts.

Overview

Facebook Login is part of the Meta for Developers platform and allows users to authenticate using their existing Facebook credentials. When a user logs in via Facebook, SIGNula receives a unique user ID, their name, profile picture URL, and email address (if granted). This provides a seamless single sign-on experience for users who prefer to use their Meta accounts.

What SIGNula Requests

SIGNula only requests the minimum permissions necessary: email (user's primary email) and public_profile (name, profile picture, locale). No additional data such as friends lists, posts, or photos is accessed.

Prerequisites

  • A Facebook account (personal account is sufficient to get started)
  • A Meta for Developers account at developers.facebook.com
  • A publicly accessible domain with HTTPS enabled for your SIGNula instance
  • Access to the SIGNula Admin Panel
Note: You will need to verify your Meta for Developers account with a phone number or payment method before you can create applications.

Step-by-Step Setup

1

Go to Meta for Developers

Visit developers.facebook.com and log in with your Facebook account. If you have not registered as a Meta developer yet, you will be prompted to complete the registration process.

2

Create a New App

Click My Apps in the top navigation bar, then click Create App.

3

Select App Type

Select the app type Consumer (recommended for user-facing login) or None for basic functionality. The Consumer type provides access to Facebook Login and other consumer-facing products.

Tip: Choose "Consumer" if you plan to allow public users to log in with Facebook. The "None" type is suitable for testing but may have limited product access.
4

Enter App Details

Fill in the following details:

  • App Name: SIGNula Login (or your preferred name)
  • App Contact Email: Your developer or admin email address

Click Create App to proceed. You may be asked to complete a CAPTCHA verification.

5

Add the Facebook Login Product

In the app dashboard, click Add Product (or find the product catalogue). Locate Facebook Login and click Set Up.

6

Select Web Platform

When asked to choose a platform, select Web. This tells Facebook that your integration will be used from a web application.

7

Enter Your Site URL

Enter your SIGNula instance URL: 

https://yourdomain.com

Click Save and then Continue. You can skip the remaining quickstart steps.

8

Configure Facebook Login Settings

In the left sidebar, navigate to Facebook Login → Settings.

9

Add Valid OAuth Redirect URIs

Under Valid OAuth Redirect URIs, add the following callback URL: 

https://yourdomain.com/oauth/callback

Click Save Changes.

Important: The redirect URI must match exactly what SIGNula sends during the OAuth flow. Ensure there are no trailing slashes or mismatched protocols (http vs https).
10

Verify OAuth Login Settings

On the same Facebook Login Settings page, ensure the following toggles are enabled:

  • Client OAuth Login: Yes
  • Web OAuth Login: Yes

These settings are typically enabled by default, but verify them to avoid authentication errors.

11

Navigate to App Settings

In the left sidebar, go to Settings → Basic.

12

Copy App ID and App Secret

On the Basic Settings page, you will find:

  • App ID: Displayed at the top of the page (a numeric string)
  • App Secret: Click Show to reveal it (you may need to re-enter your password)

Copy both values. You will need them in the next step.

Critical: Never share your App Secret publicly. Do not commit it to version control or expose it in client-side code. SIGNula stores it encrypted in the backend database.
13

Configure SIGNula Admin Panel

Log in to your SIGNula Admin Panel and navigate to:

System → OAuth Providers → Facebook

  1. Toggle the Enabled switch to activate Facebook OAuth.
  2. Paste your App ID into the "App ID" field.
  3. Paste your App Secret into the "App Secret" field.
  4. Click Save.
Security: The App Secret is stored encrypted in tblSettings (marked as isSensitive) and is never exposed in the admin UI after saving.
14

Test the Login

Open your SIGNula login page in a new browser window or incognito session. Click the Sign in with Facebook button to verify the OAuth flow works correctly. You should be redirected to Facebook, asked to grant permissions, and then returned to SIGNula with your account linked.

Success: If login completes without errors and your profile information appears in SIGNula, the integration is working correctly.

App Review & Publishing

When your Facebook app is first created, it is in Development Mode. This means only users who have been added as admins, developers, or testers can use the login functionality.

Development Mode Limitations

In development mode, only users listed under App Roles can log in via Facebook. All other users will see an error when attempting to authenticate.

To Allow All Users

  1. Complete the App Review process in the Meta for Developers dashboard.
  2. Submit the required permissions for review: email and public_profile.
  3. Provide clear instructions on how your app uses Facebook Login (screenshots and descriptions).
  4. Once approved, switch the app from Development to Live mode.
Review Timeline: App review typically takes 1-5 business days. Ensure your privacy policy URL is accessible and your app description is complete before submitting.

Adding Test Users

While in development mode, you can add test users by navigating to App Roles → Roles in the sidebar and inviting users as testers. You can also create test users under App Roles → Test Users for automated testing without using real Facebook accounts.

Scopes & Permissions

SIGNula requests the following OAuth scopes from Facebook:

Scope Description Required
email Access to the user's primary email address. Note: some users may not have an email associated with their Facebook account. Yes
public_profile Access to a user's default public profile fields: name, first name, last name, profile picture, locale, and link. Yes (default)
Note: The public_profile scope is automatically included in every login request. The email scope requires separate approval during App Review if you want non-testers to use it.

Data Deletion Callback

Facebook requires all apps that use Facebook Login to provide either a Data Deletion Callback URL or Data Deletion Instructions URL. This is part of Meta's compliance with data protection regulations such as GDPR.

Option 1: Data Deletion Callback URL (Recommended)

SIGNula provides an automatic data deletion endpoint. Configure the following URL in your Facebook app settings under Settings → Basic → Data Deletion: 

https://yourdomain.com/oauth/facebook/data-deletion

When a user requests deletion of their data through Facebook, Meta will send a POST request to this endpoint. SIGNula will then remove the Facebook association from the user's account and log the event in the activity log.

Option 2: Data Deletion Instructions URL

Alternatively, you can provide a URL that contains instructions for users on how to delete their data. This could link to your privacy policy or a dedicated data deletion request page: 

https://yourdomain.com/legal/data-deletion
Required: You must configure one of these options, otherwise your app will not pass App Review and may be suspended by Meta.

Troubleshooting

  • Your app is likely still in Development Mode. Only users added as admins, developers, or testers can log in.
  • To allow public access, complete the App Review process and switch the app to Live mode.
  • Check App Roles in the sidebar to add test users for development testing.

  • Verify the redirect URI in Facebook Login → Settings → Valid OAuth Redirect URIs matches exactly what SIGNula sends.
  • Ensure you are using https://, not http://.
  • Check for trailing slashes: https://yourdomain.com/oauth/callback is different from https://yourdomain.com/oauth/callback/.
  • If using a development environment (localhost), add https://localhost/oauth/callback to the redirect URIs as well.

  • Ensure your Privacy Policy URL is publicly accessible and accurately describes your data practices.
  • Provide clear screenshots showing how Facebook Login is used in your application.
  • Include a detailed description of why you need each permission.
  • Make sure the Data Deletion callback or instructions URL is configured.
  • Check the rejection feedback from Meta and address all listed issues before resubmitting.

  • Facebook regularly deprecates older API versions (typically a 2-year lifecycle).
  • Check the current API version at Graph API Changelog.
  • SIGNula uses the Graph API version configured in oauth.facebook.api_version. Update this setting to the latest stable version.
  • Test thoroughly after upgrading API versions, as field names or response formats may change.

  • Some Facebook accounts do not have a confirmed email (e.g., accounts registered with a phone number only).
  • Users can choose to decline sharing their email during the OAuth consent screen.
  • SIGNula handles this gracefully by prompting the user to provide an email address manually if one is not returned.
  • Ensure the email scope is included in your OAuth request.

Settings Reference

These settings are stored in tblSettings in the SIGNula backend database. Fields marked with are encrypted at rest.

Setting Key Type Description
oauth.facebook.enabled Boolean Enable or disable Facebook OAuth as a login provider
oauth.facebook.app_id String Your Facebook App ID (numeric string)
oauth.facebook.app_secret String Your Facebook App Secret (encrypted, isSensitive)
oauth.facebook.redirect_uri String OAuth callback URL (e.g., https://yourdomain.com/oauth/callback)
oauth.facebook.api_version String Facebook Graph API version (e.g., v19.0)
oauth.facebook.scopes String Comma-separated list of OAuth scopes. Default: email,public_profile
