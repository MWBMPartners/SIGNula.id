Ko-fi Setup

Integrate Ko-fi for donation-based payments, memberships, and shop orders. Ko-fi is a webhook-only integration — users pay on Ko-fi's hosted page and SIGNula is notified via webhook.

Overview

Ko-fi is a creator-focused platform that allows supporters to make one-time donations ("coffees"), recurring memberships, and shop purchases. Unlike Stripe or PayPal, Ko-fi does not provide a charge creation API. Instead, all payments happen on Ko-fi's hosted page, and SIGNula receives webhook notifications when transactions occur.

Important: Ko-fi is a webhook-only integration. There is no API to create charges or initiate payments programmatically. Users are directed to your Ko-fi page to make payments, and SIGNula receives notifications afterwards.

Integration Type

Model: Webhook-Only (no charge creation API)
Payment Page: Hosted on Ko-fi (e.g., https://ko-fi.com/yourusername)
Webhook Format: POST with application/x-www-form-urlencoded containing a data field (JSON string)
Webhook Verification: verification_token field inside the JSON payload body (NOT an HMAC signature header)

Prerequisites

  • A Ko-fi account at ko-fi.com
  • Ko-fi Gold subscription (recommended) — required for webhook functionality and advanced features
  • A publicly accessible HTTPS endpoint for webhooks
  • SIGNula Admin Panel access (for vendor setup) or Partner Dashboard access (for partner setup)
Note: Ko-fi Gold is a paid upgrade that unlocks webhooks, custom branding, and additional features. Without Ko-fi Gold, webhook functionality is not available and SIGNula cannot receive payment notifications automatically.

Part A: Vendor (Platform Owner) Setup

Follow these steps if you are the SIGNula platform owner and want to receive Ko-fi donations, memberships, and shop order notifications.

1

Create a Ko-fi Account

Visit ko-fi.com and create an account. You can sign up with an email address or link an existing Google or Apple account.

Recommendation: Upgrade to Ko-fi Gold to unlock webhook support, custom page branding, and the ability to remove Ko-fi branding from your page. This is required for the SIGNula integration to work.
2

Navigate to API Settings

Once logged in to your Ko-fi account:

  1. Click the Settings (gear icon) in the navigation.
  2. Select the API section from the settings menu.
3

Enable Webhooks

In the API settings page, toggle the Enable Webhooks switch to on. This enables Ko-fi to send POST requests to your specified URL when transactions occur.

4

Set Webhook URL

Enter your SIGNula webhook endpoint URL in the Webhook URL field: 

https://yourdomain.com/webhooks/kofi
Important: The webhook URL must use HTTPS. Ko-fi will not send webhooks to HTTP endpoints.
5

Copy the Verification Token

After enabling webhooks, Ko-fi will display a Verification Token on the same settings page. Copy this token — it is used to verify that incoming webhook payloads are genuinely from Ko-fi. 

# Example Verification Token format:
xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
Critical: Unlike other providers that use HMAC signature headers, Ko-fi includes the verification_token directly inside the webhook payload body. SIGNula compares this token against your stored token to verify authenticity.
6

Note Your Ko-fi Page URL

Your Ko-fi page URL is the public-facing page where supporters can make payments. Note it down as you will need to enter it into SIGNula. The URL follows the format: 

https://ko-fi.com/yourusername

This URL will be used in payment buttons and links throughout your application to direct users to the Ko-fi payment page.

7

Configure SIGNula Admin Panel

Now enter your credentials into SIGNula:

  1. Log in to your SIGNula Admin Panel.
  2. Navigate to Admin → Payments → Providers → Ko-fi.
8

Enter Verification Token and Page URL

In the Ko-fi provider settings:

  • Paste your Verification Token into the corresponding field.
  • Enter your Ko-fi Page URL (e.g., https://ko-fi.com/yourusername).
Security: The Verification Token is stored encrypted in the SIGNula database (marked as isSensitive) and is only decrypted when processing incoming webhooks.
9

Enable Ko-fi Gold Toggle

If you have a Ko-fi Gold subscription, enable the Ko-fi Gold toggle in the SIGNula admin panel. This unlocks additional event types and features in the webhook integration.

10

Test Connection and Enable

Click the Test Connection button. Since Ko-fi does not provide a dedicated test API endpoint, the test will:

  • Verify that the Verification Token is in a valid format.
  • Confirm the webhook endpoint is configured and reachable.
  • Validate the Ko-fi Page URL is accessible.

Once the test passes, toggle the Enabled switch to activate Ko-fi as a payment provider.

Success: Ko-fi is now configured. Supporters who make payments on your Ko-fi page will trigger webhook notifications to SIGNula.

Part B: Partner Setup

Partners who want to receive Ko-fi payments through their own page must set up their own Ko-fi account and provide their credentials to SIGNula.

1

Create Your Own Ko-fi Page

Each partner must create their own Ko-fi account and page at ko-fi.com. Ko-fi Gold is recommended for webhook support.

2

Configure Webhooks on Ko-fi

Follow the same webhook setup steps as Part A, but set your webhook URL to your partner-specific endpoint provided by SIGNula: 

https://yourdomain.com/webhooks/kofi/{partner_id}
3

Enter Credentials in Partner Dashboard

In your SIGNula Partner Dashboard, navigate to Settings → Payment Providers → Ko-fi and enter:

  • Your Verification Token from Ko-fi's API settings
  • Your Ko-fi Page URL
  • Your Ko-fi Page Slug (username portion of your URL)
  • Whether you have Ko-fi Gold enabled

Webhook Configuration

Key Difference: Ko-fi webhooks are fundamentally different from other providers. Ko-fi sends a POST request with application/x-www-form-urlencoded content type. The body contains a single data field whose value is a JSON string (not raw JSON). You must parse this data field as JSON to access the event details.

Webhook Payload Structure

// Raw POST body (application/x-www-form-urlencoded):
// data={JSON_STRING}
//
// Decoded JSON structure:
{
    "verification_token": "your-token-here",
    "message_id": "xxxx-xxxx-xxxx",
    "timestamp": "2026-02-19T12:00:00Z",
    "type": "Donation",
    "is_public": true,
    "from_name": "Supporter Name",
    "message": "Great work!",
    "amount": "5.00",
    "url": "https://ko-fi.com/Home/CoffeeShop?txid=xxxx",
    "email": "supporter@example.com",
    "currency": "USD",
    "is_subscription_payment": false,
    "is_first_subscription_payment": false,
    "kofi_transaction_id": "xxxx-xxxx-xxxx"
}

Event Types

Event Type Description SIGNula Action
Donation A one-time "coffee" donation payment Records donation; credits account if applicable
Subscription A recurring membership payment Activates/renews membership tier
Shop Order A purchase from the Ko-fi shop Records shop order; triggers fulfilment

Webhook Verification (Payload Token)

Ko-fi does not use HMAC signature headers. Instead, every webhook payload includes a verification_token field. SIGNula compares this token against the stored token to verify authenticity. 

// Webhook verification in PHP (simplified)
// Ko-fi sends application/x-www-form-urlencoded with a 'data' field
$rawData = $_POST['data'] ?? '';
$data    = json_decode($rawData, true);

if (json_last_error() !== JSON_ERROR_NONE || empty($data)) {
    http_response_code(400);
    exit('Invalid payload');
}

// Retrieve stored token (decrypted from tblSettings)
$storedToken = $decryptedVerificationToken;

// Compare the verification_token from the payload
if (!isset($data['verification_token']) ||
    !hash_equals($storedToken, $data['verification_token'])) {
    http_response_code(401);
    exit('Invalid verification token');
}

// Token valid - process the event
$eventType = $data['type'] ?? 'Unknown';
$amount    = $data['amount'] ?? '0.00';
$fromName  = $data['from_name'] ?? 'Anonymous';
No Test/Sandbox Mode: Ko-fi does not provide a sandbox or test environment. To test webhooks, use a small real donation amount (e.g., the minimum allowed). Alternatively, you can manually send a test POST request to your webhook endpoint with a sample payload containing your verification token.

Troubleshooting

Webhooks are not being received

  • Confirm you have Ko-fi Gold — webhooks require a Gold subscription.
  • Verify that webhooks are enabled in Ko-fi Settings → API.
  • Check that your webhook URL uses HTTPS and is publicly accessible.
  • Ensure your server returns a 200 OK response quickly (within a few seconds).
  • Check your server's access logs for incoming POST requests from Ko-fi.

Verification token mismatch

  • Ensure the token in SIGNula exactly matches the one shown in Ko-fi Settings → API.
  • Check that you are parsing the data POST field as JSON before comparing tokens.
  • Verify no URL decoding issues are modifying the token value.
  • Try re-copying the token from Ko-fi and updating it in SIGNula.

Payload parsing errors

  • Remember: Ko-fi sends application/x-www-form-urlencoded, NOT application/json.
  • Read the data field from $_POST['data'], not from php://input directly.
  • The data field value is a JSON string that must be decoded with json_decode().
  • Check that your PHP configuration allows URL-encoded POST data of sufficient size.

Subscription events not triggering tier activation

  • Check the type field in the payload — it should be Subscription.
  • Verify that is_subscription_payment is true.
  • For first-time subscriptions, is_first_subscription_payment will be true.
  • Ensure you have mapped Ko-fi subscription tiers to SIGNula tiers in the admin panel.

Ko-fi Gold features not working

  • Verify your Ko-fi Gold subscription is active and not expired.
  • Ensure the payment.kofi.gold_enabled toggle is set to true in SIGNula.
  • Some features (such as shop orders) may require additional Ko-fi Gold configuration on the Ko-fi platform itself.

Reference

Webhook Payload Fields

Field Type Description
verification_token String Token for verifying the webhook origin
message_id String Unique identifier for the transaction message
timestamp String (ISO 8601) Timestamp of the transaction
type String Event type: Donation, Subscription, or Shop Order
from_name String Display name of the supporter
message String Optional message from the supporter
amount String Payment amount (e.g., "5.00")
currency String Currency code (e.g., USD, GBP)
email String Supporter's email address (if provided)
is_subscription_payment Boolean Whether this is a recurring subscription payment
is_first_subscription_payment Boolean Whether this is the first payment of a new subscription
kofi_transaction_id String Ko-fi's unique transaction identifier

Settings Reference (tblSettings)

Fields marked with are encrypted at rest (isSensitive = true).

Setting Key Type Description
payment.kofi.enabled Boolean Enable or disable Ko-fi as a payment provider
payment.kofi.verification_token String Ko-fi webhook verification token (encrypted, isSensitive)
payment.kofi.page_url String Full Ko-fi page URL (e.g., https://ko-fi.com/yourusername)
payment.kofi.page_slug String Ko-fi username/slug (e.g., yourusername)
payment.kofi.gold_enabled Boolean Whether Ko-fi Gold features are active for this account
