Sign in with SIGNula.id

A framework-free, copy-paste button any partner site can embed to let its users authenticate with a SIGNula ID — the same pattern as "Sign in with Google" / "Sign in with Apple". This page shows every visual variant and size, the exact snippet to copy, and a live (non-navigating) preview of the PKCE values the button generates on click.

Copy-paste snippet

Paste this into any HTML page — no build step, no framework:

Swap data-client-id / data-redirect-uri for your own registered values (see README.md), and self-host the two asset files if you prefer not to load them from signula.id. Full data-* option reference is in README.md.

Variants

--light (default)
--dark
--brand (gradient fill)
--mono (colour-blind-safe, light)
--mono (colour-blind-safe, dark)

Auto dark-mode: a bare .signula-btn (no --light/--dark/--brand/--mono modifier) automatically follows your OS/browser dark-mode preference AND a [data-theme="dark"] ancestor — toggle your OS appearance to see it switch without any extra markup.

Sizes

The icon-only button keeps its label for assistive technology (visually hidden, not display:none) — no separate aria-label is required, though one is harmless if you add it (shown above for clarity).

What happens on click

  1. signula-signin.js generates a random 32-byte code_verifier, hashes it with SHA-256, and base64url-encodes the digest as code_challenge (RFC 7636, S256).
  2. A random state and nonce are generated (16 bytes each).
  3. code_verifier + nonce are saved to sessionStorage under the key signula:pkce:<state> — never sent anywhere at this point.
  4. The browser navigates to <signula-base>/oauth/authorize-idp with response_type=code, your client_id, redirect_uri, scope, state, nonce, code_challenge and code_challenge_method=S256.
  5. The user authenticates/consents on SIGNula, which redirects back to your redirect_uri with ?code=...&state=....
  6. Your backend verifies state, looks up the stored code_verifier, and exchanges the code at POST /oauth/token — see README.md and /docs/signin-with-signula for that half of the flow.

Live technical preview

This button calls the real SignulaSignin.generateCodeVerifier() / SignulaSignin.s256() functions shipped in signula-signin.js and prints the values + the authorize URL that would be visited — but deliberately does not navigate away, so you can safely try it on this offline demo page. (It intentionally has no data-client-id attribute, so signula-signin.js's own auto-wiring skips it; this section wires it up separately, below.)

Needs a secure context (https:// or http://localhost) — the Web Crypto API this relies on is unavailable on a plain file:// page in most browsers. If the output below shows an error immediately, that's why; the actual drop-in shows the same graceful error on a partner's page instead of a broken redirect.
